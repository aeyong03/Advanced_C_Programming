# [SECTION 1] 문법 기술 서술형 문제

### Q1. 배열 이름과 포인터 변수의 공통점과 차이점(2가지 이상)을 기술하시오.
- **[모범 답안]**
  - **공통점**: 둘 다 메모리의 주솟값을 나타내며, `*` 역참조 연산자와 `[]` 인덱스 연산자를 동일하게 사용할 수 있다 (`arr[i] == *(arr + i)`).
  - **차이점**:
    1. 배열 이름은 첫 번째 원소의 주소를 고정으로 가리키는 **'포인터 상수(Pointer Constant)'**이므로 다른 주소를 대입하거나 변경할 수 없다 (`arr = p;` 불가, `arr++` 불가). 반면 포인터 변수는 주소를 저장하는 **'변수(Variable)'**이므로 자유롭게 다른 주소를 대입하거나 값을 증감시킬 수 있다.
    2. `sizeof` 연산 시, 배열 이름은 **배열 전체가 차지하는 메모리 크기(바이트)**를 반환하지만, 포인터 변수는 **포인터 자체의 크기(32비트 환경 4바이트, 64비트 환경 8바이트)**만을 반환한다.

### Q2. `free(ptr);` 함수를 호출한 이후에도 `ptr = NULL;`을 명시적으로 실행해 주어야 하는 이유와, C언어 컴파일러가 이를 자동으로 처리해 주지 못하는 이유를 기술하시오.
- **[모범 답안]**
  - **이유**: `free(ptr)`을 호출하면 힙 영역에 할당되었던 메모리만 운영체제에 반납될 뿐, `ptr` 변수에 저장된 주솟값은 그대로 남아있다. 이 상태의 포인터를 **댕글링 포인터(Dangling Pointer)**라고 부르며, 이후 실수로 이 포인터를 통해 값을 읽거나 쓰게 되면 쓰레기값을 읽거나 메모리를 오염시켜 프로그램이 비정상 종료(Crash)될 수 있다. 따라서 더 이상 유효하지 않은 주소를 가리키지 못하도록 `ptr = NULL;`로 초기화해야 한다.
  - **컴파일러가 자동 처리하지 못하는 이유**: C언어의 함수 인자 전달은 **값에 의한 전달(Call by Value)** 방식을 따른다. `free(ptr)`에 전달되는 것은 `ptr` 변수의 값(주소 복사본)이므로, `free()` 함수 내부에서 매개변수를 아무리 수정해도 호출자 영역에 있는 원본 변수 `ptr`의 값을 `NULL`로 변경할 수 없기 때문이다.

### Q3. `int *p[3];`과 `int (*p)[3];`의 문법적 의미와 차이점을 구체적으로 기술하시오.
- **[모범 답안]**
  - **`int *p[3];` (포인터 배열)**:
    대괄호 `[]`가 `*`보다 연산자 우선순위가 높아 배열이 먼저 결합된다. 즉, **"정수형 포인터(`int*`) 3개를 저장할 수 있는 크기 3의 배열"**이다.
  - **`int (*p)[3];` (배열 포인터)**:
    괄호 `()`에 의해 `*`가 먼저 결합된다. 즉, **"원소가 3개인 정수형 배열(`int[3]`)을 통째로 가리키는 포인터 변수 1개"**이다. (주로 2차원 배열을 함수 매개변수로 전달받을 때 사용됨)

# [SECTION 2] 문법 O / X 퀴즈

**[Q4 ~ Q13] 다음 코드나 문장의 문법적/동작적 타당성을 O 또는 X로 표시하시오.**

4. `int a = 10; int *p = &a; *p = 20;` 실행 후 `a`의 값은 20이 된다.  
   👉 **[ 정답: (  O  ) ]** : 역참조를 통해 원본 변수 `a`의 메모리에 20을 대입함.

5. `int arr[5] = {1, 2, 3, 4, 5};` 일 때, `*(arr + 3)`과 `3[arr]`은 문법적으로 동일하며 값 4를 갖는다.  
   👉 **[ 정답: (  O  ) ]** : `*(arr + 3) == *(3 + arr) == 3[arr]`로 C언어 문법상 유효함.

6. `char *s = "Hello"; s[0] = 'h';`는 컴파일 에러 없이 정상 실행되어 "hello"로 출력된다.  
   👉 **[ 정답: (  X  ) ]** : 문자열 리터럴은 읽기 전용 메모리에 위치하므로 런타임 Crash 발생.

7. `int *p = (int*)malloc(sizeof(int) * 5);`로 할당된 5개의 원소는 모두 자동으로 0으로 초기화된다.  
   👉 **[ 정답: (  X  ) ]** : `malloc`은 초기화하지 않아 쓰레기값을 가짐. 0 초기화는 `calloc`.

8. `void test(int arr[10]) { sizeof(arr); }`에서 `sizeof(arr)`는 40(또는 80) 바이트가 나온다.  
   👉 **[ 정답: (  X  ) ]** : 함수 매개변수의 배열은 포인터로 decay되므로 포인터 크기(4B 또는 8B)가 출력됨.

9. `int *p; *p = 100;`은 문법적으로 아무런 문제가 없으며 안전한 코드이다.  
   👉 **[ 정답: (  X  ) ]** : 포인터 `p`가 초기화되지 않아 알 수 없는 주소를 가리키므로 정의되지 않은 동작(UB/Crash).

10. `realloc(p, new_size)` 함수는 기존 메모리의 데이터를 보존하면서 크기를 변경한다.  
    👉 **[ 정답: (  O  ) ]** : 기존 데이터는 그대로 보존되며 크기가 늘어난 부분만 쓰레기값임.

11. `char **p;`에서 `p + 1`을 하면 실제 메모리 주소는 1바이트 증가한다.  
    👉 **[ 정답: (  X  ) ]** : `p`는 `char*` 포인터들을 가리키므로, 포인터 크기(4바이트 또는 8바이트)만큼 증가함.

12. 2차원 동적 메모리를 해제할 때 바깥 포인터 배열을 먼저 `free`해도 내부 메모리는 알아서 정리된다.  
    👉 **[ 정답: (  X  ) ]** : 바깥 포인터를 먼저 해제하면 안쪽 주소를 잃어버려 심각한 메모리 누수 발생.

13. `int arr[5];`에서 `&arr`과 `arr`은 동일한 주솟값을 출력하지만, 두 표현식의 포인터 타입은 서로 다르다.  
    👉 **[ 정답: (  O  ) ]** : 값은 같지만 `arr`은 `int*` 타입이고, `&arr`은 `int (*)[5]`(배열 전체를 가리키는 포인터) 타입임.

# [SECTION 3] 코드 오류 찾기 및 올바른 문법으로 수정하기

### Q14. [실습 1 예제 변형] 다음 두 수의 값을 교환(Swap)하려는 함수와 호출부이다. 잘못된 줄 2곳을 찾아 바르게 수정하시오.
```c
01 void swap(int *a, int *b) {
02     int temp;
03     temp = a;
04     a = b;
05     b = temp;
06 }
07 int main() {
08     int x = 10, y = 20;
09     swap(x, y);
10     return 0;
11 }
```
- **[오류 및 수정]**
  - **03~05행 오류**:
    - `temp = *a; *a = *b; *b = temp;` 로 수정해야 함. (역참조 `*` 누락으로 주소만 바꾸고 원본 값 변경 실패)
  - **09행 오류**:
    - `swap(&x, &y);` 로 수정해야 함. (함수가 포인터를 받으므로 주소 연산자 `&` 전달 필요)

### Q15. [예제 12-7 변형] 사용자로부터 입력받은 문자열을 포인터 배열에 동적 할당하여 저장하는 코드이다. 오류 2곳을 찾아 수정하시오.
```c
01 char *p[3];
02 char imsi[100];
03 for (int i = 0; i < 3; i++) {
04     scanf("%s", imsi);
05     p[i] = (char*) malloc(strlen(imsi));
06     strcpy(p[i], imsi);
07 }
08 free(p);
```
- **[오류 및 수정]**
  - **05행 오류**:
    - `p[i] = (char*) malloc(strlen(imsi) + 1);`  
    - 문자열 끝의 **널 문자(`\0`)를 위한 1바이트(`+ 1`)**가 빠져 메모리 침범 버그 발생.
  - **08행 오류**:
    - `free(p);` 단독 사용 불가!  
    - `p`는 정적 배열이므로 `free(p)` 자체가 문법 에러이며, 개별 할당된 요소들을 해제해야 함:
      ```c
      for (int i = 0; i < 3; i++) {
          free(p[i]);
      }
      ```

### Q16. [문자열 복사 함수 직접 구현] 다음 `my_strcpy` 함수에서 문법적/동작적 치명적 결함을 찾아 수정하시오.
```c
01 void my_strcpy(char *dest, char *src) {
02     while (*src != '\0') {
03         *dest = *src;
04         dest++;
05         src++;
06     }
07 }
```
- **[오류 및 수정]**
  - **06행 뒤에 누락**:
    - `*dest = '\0';` 코드 추가 필요.
    - 원본 문자열의 끝을 나타내는 널 문자가 복사되지 않아 대상 문자열이 손상됨.

# [SECTION 4] 코드 빈칸 채우기

### Q17. [동적 할당 크기 확장 - 예제 12-5]
사용자가 0을 입력할 때까지 숫자를 계속 입력받아 동적으로 배열을 1칸씩 늘리는 코드이다. 빈칸 ①, ②를 채우시오.
```c
int *p = (int*) malloc(sizeof(int) * 1);
int cnt = 1, num;

while (1) {
    scanf("%d", &num);
    if (num == 0) break;
    
    cnt++;
    // 새로운 크기(cnt)로 메모리 재할당
    p = (int*) [    ①    ](p, sizeof(int) * [    ②    ]);
    p[cnt - 1] = num;
}
```
- **정답**:
  - **①**: `realloc`
  - **②**: `cnt`

### Q18. [이중 포인터 동적 할당 및 해제]
행(Row)의 개수가 `R`개, 열(Column)의 개수가 `C`개인 2차원 정수 행렬을 동적 할당하고 해제하는 코드이다. 빈칸을 채우시오.
```c
int **matrix = (int**) malloc(sizeof([    ①    ]) * R);

for(int i = 0; i < R; i++) {
    matrix[i] = (int*) malloc(sizeof([    ②    ]) * C);
}

// 메모리 해제
for(int i = 0; i < R; i++) {
    [    ③    ](matrix[i]);
}
[    ③    ](matrix);
```
- **정답**:
  - **①**: `int*`
  - **②**: `int`
  - **③**: `free`
